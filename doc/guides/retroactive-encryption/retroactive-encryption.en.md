# Retroactive Encryption: Remove Plain Text from Git History

## Problem

`veil_setup.py` detected that files matching your chosen patterns already exist in git
history as plain text. This means anyone with access to the repository can read those files,
even after you configure encryption going forward.

Encrypting from this point protects only **future** commits. To remove plain text from
past history, you must rewrite the git history using `git filter-repo`.

> **⚠ Warning:** History rewrite is irreversible and affects every collaborator.
> All existing clones must be re-cloned after you force-push the rewritten history.

---

## Prerequisites

Install `git filter-repo`:

```bash
pip install git-filter-repo
# macOS alternative:
brew install git-filter-repo
```

Verify: `git filter-repo --version`

---

## Step-by-step Instructions

### Step 1 — Back up the files

Copy the sensitive files **outside** the repository before `filter-repo` removes them:

```bash
cp -r path/to/sensitive/ /tmp/veilgit_backup/
```

### Step 2 — Remove files from the entire git history

```bash
git filter-repo --path path/to/sensitive/ --invert-paths
```

For multiple paths, repeat `--path`:

```bash
git filter-repo \
  --path docs/private/ \
  --path secrets/ \
  --invert-paths
```

After this command, the files are gone from the working directory **and** from every
commit in the history.

### Step 3 — Verify removal

```bash
git log --all --oneline -- path/to/sensitive/
# must return no output
```

### Step 4 — Restore files to the working directory

```bash
cp -r /tmp/veilgit_backup/ path/to/sensitive/
```

### Step 5 — Re-initialize veilgit filters

`git filter-repo` resets `.git/config`. Re-register the veilgit git filters:

```bash
python veil_setup.py . --reinit
```

### Step 6 — Stage config and encrypted files

```bash
# Stage veilgit configuration first
git add .gitattributes .veil/

# Stage the restored files — the clean filter encrypts them during git add
git add path/to/sensitive/

git commit -m "chore: retroactively encrypt sensitive files"
```

### Step 7 — Force-push the rewritten history

```bash
git push --force-with-lease origin main
```

`--force-with-lease` is safer than `--force`: it fails if the remote has commits you do
not have locally, preventing accidental overwrites.

### Step 8 — Notify collaborators

All existing clones diverge after the force-push. Every collaborator must re-clone:

```bash
git clone <repo_url>
cd <repo>
bash .veil/setup_veil.sh /path/to/their_private_key.txt
```

---

## Verify Encryption

After committing, confirm that git stores only encrypted content:

```bash
git show HEAD:path/to/sensitive/yourfile.md | xxd | head -3
# first bytes should be the age encryption header, not plain text
```

---

## Notes on GitHub Caches

GitHub may retain cached objects referencing the old history for a short period.
For maximum security (e.g., before making the repository public), contact
[GitHub Support](https://support.github.com) to request a cache purge after the force-push.
